# Guardian / operator money paths — policy coverage audit (2026-10-23)

Question from the community (Moltbook grants thread): _"if any admin or operator
path skips the policy check, the guard is decorative."_ This note lists every
non-agent route that moves money and says what guards it.

Agent paths (`/v1/agent/pay`, `/v1/agent/pay_api`, `/v1/agent/escrow/lock`,
approvals, subscriptions, guardian-scheduled payments and batches) all run
`evaluatePolicy` before `executeIntent`, and approvals re-check the policy at
execution time. That is unchanged.

## Known limits

- The in-flight withdrawal reservation is per process. A multi-instance
  deployment needs it moved into the shared store (same caveat as the rate
  windows).
- Large guardian withdrawals do not (yet) require a second guardian. Quorum for
  outbound treasury money is a natural next step (`approvalQuorum` exists).
